| 指标       | 结果     |

# EXP-004 — 学习率扫描

### 目标

为 baseline 寻找合适的学习率，并考察收敛速度与训练稳定性边界之间的关系。

### 搜索策略

覆盖从保守到激进的学习率，固定其余超参（batch=64，327M tokens）。

| 学习率 | 最佳验证损失 | 是否发散 | 备注                 |
| -----: | -----------: | -------- | -------------------- |
| 1e-4   | 1.4724       | 否       | 偏小，欠拟合         |
| 3e-4   | 1.3470       | 否       | 消融实验的对照基线   |
| 1e-3   | 1.3013       | 否       |                      |
| **3e-3** | **1.2960** | 否       | **最优**             |
| 5e-3   | 1.3175       | 否       | 越过谷底，开始回升   |
| 1e-2   | 1.4073       | 否       | 明显变差             |
| 3e-2   | 1.7426       | 否       | 很差，但仍收敛未发散 |

### 学习曲线

![学习率扫描（验证损失对比）](../figures/light/lr_sweep.png)

### 发现

1. **典型的 U 型曲线**：验证损失随学习率先降后升，谷底在 **3e-3**（1.296）。最佳学习率两侧对称升高：1e-4 因步长太小欠拟合（1.47），1e-2/3e-2 因步长过大在噪声中震荡、收敛质量下降（1.41 / 1.74）。
2. **收敛速度与最佳学习率**：越靠近最佳学习率，验证损失下降越快、终值越低；越激进则越早进入高噪声平台期。
3. **稳定性边界远高于预期**：学习率一路加到 3e-2 都没有发散。为进一步刻画稳定性边界，做了专门的发散探索，见下。

### 稳定性边界探索（发散实验）

为完整刻画训练稳定性，需要至少一个发散 run。但本实现的训练异常稳定，追查发散边界的过程本身很有启发：

| 配置                      | 结果                                    |
| ------------------------- | --------------------------------------- |
| 有梯度裁剪，lr=3e-2       | 收敛（1.74）                            |
| 有梯度裁剪，lr=1e-1       | 不发散（8000+ 步 loss 稳在 2.48）       |
| 关闭梯度裁剪，lr=1e-2     | 不发散，但 loss 变差到 2.0（对比有裁剪的 1.407）|
| **关闭梯度裁剪，lr=1.0**  | **step 174 发散**（train loss 爆炸至 25.98）|

![发散曲线：关裁剪 + lr=1.0，step ~145 起急剧爆炸](../figures/light/baseline_noclip_lr1_curve.png)

**机理**：稳定性由两道防线共同维持——

1. **梯度裁剪（max_norm=1.0）**：把每步梯度范数强行限制，无论 lr 多大，单步更新都受控 → 这就是为什么有裁剪时 lr 加到 3e-2 / 1e-1 都不炸。
2. **AdamW 的自适应更新**：更新量 ≈ lr × m̂/(√v̂+ε) ≈ lr × O(1)，对梯度尺度做了归一化 → 这就是为什么即使关掉裁剪，lr=1e-2 仍能稳住（只是效果变差）。

只有**同时**突破两者（关裁剪 + lr 大到 1.0）才会发散：如图，loss 先正常下降到 ~5.5，在 step ~145 后急剧上升、step 174 触发发散保护退出。

**复现命令**：`uv run train_experiment.py baseline --lr 1.0 --max_grad_norm 1e9 --tag noclip_lr1`

### 结论

最佳学习率为 **3e-3**，位于 U 型曲线谷底。真正的洞察是：**稳定性来自梯度裁剪与 AdamW 自适应的叠加**——单调加大 lr 很难发散，必须同时移除裁剪并施加极大 lr 才能触发。这比“调大 lr 就发散”的朴素预期深刻得多，是一个值得在报告中重点讨论的工程细节。

# EXP-005 — Batch Size 扫描

### 目标

考察 batch size 对优化行为、运行时间与最终验证损失的影响，并找出 4090 的显存上限。固定 lr=3e-4、总 tokens=327M（bs=1 因步数过多改用 20M 短预算，仅看趋势）。

### 结果

| Batch Size | 最佳验证损失 | 步数    | 运行时间 | 备注                     |
| ---------: | -----------: | ------: | -------: | ------------------------ |
| 1          | 1.7406       | 78,125  | 1329 s   | 20M 短预算；梯度噪声最大 |
| **16**     | **1.3218**   | 80,000  | 1721 s   | **最优**                 |
| 64         | 1.3424       | 20,000  | 1462 s   | 默认配置                 |
| 128        | 1.3735       | 10,000  | 1398 s   |                          |
| 160        | 1.3910       | 8,000   | 1401 s   |                          |
| 192        | 1.4035       | 6,666   | 1385 s   | **4090 可稳定训练的最大 batch** |
| 224        | —            | —       | —        | **CUDA OOM（显存不足）** |

### 学习曲线

![Batch size 扫描（验证损失对比）](../figures/light/batch_sweep.png)

### 发现

1. **存在“甜点区”，并非越大越好**：在固定 token 预算下，**bs=16 验证损失最低（1.3218）**。原因是 total_tokens 固定时，小 batch 的参数更新次数更多（bs=16 走 80000 步 vs bs=128 仅 10000 步），更充分；而 batch 越大、更新次数越少，终值越高（128→1.37，192→1.40）。
2. **极小 batch 反而最差**：bs=1（1.74）梯度噪声过大，即便更新次数最多也难收敛好——小 batch 有下限。
3. **显存精确上限**：**192 能稳定训练、224 直接 OOM**，故 4090 (24GB) 在本配置下的 batch 上限落在 192~224 之间。
4. **墙钟效率的权衡**：小 batch 虽终值低，但步数暴涨导致墙钟更久（bs=16 用 1721 s vs bs=128 用 1398 s）；bs=1 若不采用短预算，跑满 327M 需十几小时。**综合终值与 wall-clock，bs=64 是最实用的折中**。

### 结论

Batch size 与最终性能是非单调关系，存在甜点区（此处为 16）；同时验证了“越大不一定越好”。工程上 bs=64 兼顾效果与效率，bs=192 是硬件上限。

# EXP-006 — 文本生成

### 目标

从训练好的模型（EXP-003 的最佳 checkpoint，lr=3e-3）自回归生成文本，定性评估流畅度。

### 生成配置

| 参数        | 值                       |
| ----------- | ------------------------ |
| Checkpoint  | `baseline_best.pt`（lr=3e-3） |
| Temperature | 0.8                      |
| Top-p       | 0.9                      |
| Prompt      | "Once upon a time"       |
| 最大 token  | 256                      |

### 生成文本

```text
Once upon a time, there was a big bear. The bear was very independent. He liked to do
things by himself. One day, the bear was walking in the woods. He saw a big tree and
wanted to climb it. The bear climbed the tree. He saw a bird and said, "Hi, bird! Can I
climb you?" ... The big bear and the little bear became friends. They played together in
the woods. The big bear was not so independent anymore. He was happy to have a new
friend. And they both lived happily ever after.
```

### 定性评估

- **流畅度**：高。语法正确、句子通顺，具备完整的“起因—经过—结尾”故事结构（甚至有 "lived happily ever after" 这类 TinyStories 典型收尾），并正确生成 `<|endoftext|>` 结束。
- **优点**：局部连贯、用词自然、故事框架完整。
- **缺点**：存在**重复退化**（"I can do many things by myself" 反复出现）和**角色/逻辑不一致**（"big bear" 与 "little bear" 指代混乱、"Can I climb you?" 语义奇怪）——这是小模型（17M）+ 有限训练的典型局限。

### 影响生成质量的因素

1. 模型训练质量（验证损失越低，生成越连贯）；
2. 采样参数（temperature、top-p 控制随机性与多样性/重复的权衡）；
3. 模型容量与训练 token 量（17M 参数、327M tokens 决定了能力上限）。

# EXP-007 — RMSNorm 消融

### 目标

考察从 Transformer block 中移除 RMSNorm 的影响。固定 lr=3e-4，对照同 lr 的标准模型（1.3470）。

### 结果

| 配置              | 最佳验证损失 | 是否发散              |
| ----------------- | -----------: | --------------------- |
| 标准（含 RMSNorm）| 1.3470       | 否                    |
| 去掉 RMSNorm      | 2.6565       | **是（step 1842 训练损失爆炸到 114）** |

![消融对比（含 no_norm 发散曲线）](../figures/light/ablations.png)

### 发现与结论

在与标准模型相同的学习率（3e-4）下，**去掉 RMSNorm 的模型在 1842 步就发散**（训练损失从正常值骤增到 114，触发发散保护退出）。这直接证明 **RMSNorm 对 Transformer 训练稳定性是决定性的**——它把每层激活的数值尺度约束在稳定范围内，缺失后残差流的数值迅速失控。一个自然的后续问题是“能否用更低学习率恢复稳定”，可作为补充实验（预期用显著更小的 lr 能稳住，但收敛更慢）。

# EXP-008 — Pre-Norm vs. Post-Norm

### 目标

对比 pre-norm 与 post-norm 两种 Transformer block 结构（均 lr=3e-4）。

### 结果

| 结构      | 最佳验证损失 |
| --------- | -----------: |
| Pre-Norm（标准） | **1.3470** |
| Post-Norm | 1.3981       |

### 发现与结论

Pre-Norm（1.347）明显优于 Post-Norm（1.398）。Pre-Norm 把归一化放在子层输入侧，使残差路径保持“干净”的恒等映射，梯度更易回传、训练更稳、终值更低。这与现代 Transformer 普遍采用 pre-norm 的共识一致。

# EXP-009 — RoPE vs. NoPE

### 目标

对比使用 RoPE 与完全不加位置编码（NoPE）的模型（均 lr=3e-4）。

### 结果

| 结构 | 最佳验证损失 |
| ---- | -----------: |
| RoPE（标准） | 1.3470 |
| NoPE | 1.3447       |

### 发现与结论

**NoPE（1.3447）与 RoPE（1.3470）几乎持平，甚至略低**——一个有意思的“负结果”。原因：decoder-only 模型的**因果掩码本身就隐式携带了位置信息**（每个位置能看到的上文数量不同），在 TinyStories 这类**短序列（context=256）、结构简单**的任务上，显式位置编码带来的增益很小。需要强调的是，这不代表 RoPE 无用——在更长上下文和长度外推场景下 RoPE 的优势才会显现，本实验的短序列设定掩盖了它。

# EXP-010 — SwiGLU vs. SiLU

### 目标

对比默认的 SwiGLU 前馈网络与无门控的 SiLU 前馈网络，参数量近似对齐（均 lr=3e-4）。

### 配置

| 模型     | 激活   | 矩阵数 | d_ff  | FFN 参数量 |
| -------- | ------ | ------ | ----: | ---------: |
| 标准     | SwiGLU | 3      | 1,344 | ≈ 2.06M    |
| 消融     | SiLU   | 2      | 2,048 | ≈ 2.10M    |

> d_ff 的搭配：SwiGLU 用 8/3·d_model=1344（3 个矩阵），SiLU 用 4·d_model=2048（2 个矩阵），两者参数量都 ≈ 8·d²，从而公平对比“有无门控”。

### 结果

| 模型   | 最佳验证损失 |
| ------ | -----------: |
| SwiGLU（标准） | **1.3470** |
| SiLU   | 1.3759       |

### 发现与结论

在参数量对齐的前提下，**SwiGLU（1.347）优于 SiLU（1.376）**，说明**门控机制（GLU）确实带来收益**——`SiLU(W1·x) ⊙ (W3·x)` 的逐元素门控让 FFN 能对信息做输入相关的选择性放缩，表达力强于无门控的 `W2·SiLU(W1·x)`。这与 Shazeer(2020) 的结论一致。

# 综合发现

## 优化（超参）

- **最佳学习率 = 3e-3**，位于 U 型曲线谷底；两侧对称升高。
- **稳定性由梯度裁剪 + AdamW 自适应共同维持**：lr 加到 3e-2 仍不发散；只有同时关闭梯度裁剪且 lr=1.0，才在 step 174 发散（见 EXP-004）。单调加大 lr 不足以触发发散。
- **Batch size 有甜点区（16）**，非越大越好；bs=64 是效果/效率的实用折中；4090 显存上限为 **192**。

## 架构（消融）

| 组件         | 结论                                   |
| ------------ | -------------------------------------- |
| RMSNorm      | **决定性**：去掉即发散                 |
| 归一化位置   | Pre-Norm > Post-Norm                   |
| 位置编码     | NoPE ≈ RoPE（短序列任务下）            |
| FFN 门控     | SwiGLU > SiLU（门控有效）              |

**架构组件重要性排序**：RMSNorm（稳定性，最关键） > 门控 SwiGLU ≈ Pre-Norm（性能） > 位置编码（此任务下影响最小）。

## 生成

模型能生成语法正确、结构完整的短故事，但存在重复退化与逻辑不一致——受限于 17M 的模型容量与训练规模。

# 最终总结

### 最佳配置

| 组件         | 设置           |
| ------------ | -------------- |
| 词表大小     | 10,000         |
| Context 长度 | 256            |
| 模型规模     | ~17M（非嵌入） |
| 学习率       | **3e-3**       |
| Batch size   | 64（实用）/ 16（终值最优） |
| 优化器       | AdamW          |
| **最佳验证损失** | **1.2994** |

### 主要结论

1. **超参调优**：最佳 lr=3e-3，最佳配置验证损失 1.2994，远优于目标门槛 1.45。
2. **RMSNorm 是训练稳定性的关键**——移除后在相同 lr 下迅速发散。
3. **架构共识得到验证**：Pre-Norm > Post-Norm、SwiGLU > SiLU（门控有效）。
4. **NoPE ≈ RoPE**：短序列 + 因果掩码下，显式位置编码增益有限（有意思的负结果）。
5. **Batch size 存在甜点区**：并非越大越好，且受显存上限约束（4090 上限 192）。
